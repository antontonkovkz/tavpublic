# Проверка замечаний и исправления

[English](REVIEW.en.md)

Проверена версия после коммита 6e3dfda. Замечания относятся к реальным местам в коде;
ниже отделены исправления от оставшихся ограничений. Изменения не запускают ранее
остановленные клиент и сервер и не меняют настройки защиты рабочей машины.

| № | Проверка и результат |
| --- | --- |
| 1 | Подтверждено. Обработка каждого spool-файла независима. Невалидные JSON → .bad, окончательные HTTP-ошибки → .rejected; сетевые ошибки сохраняют ответ для повтора и не блокируют poll. Добавлен flush/fsync перед replace. |
| 2 | Подтверждено. Протокол 2: claimed с 60-секундной выдачей и случайным ключом, отдельный /start, затем running. Просроченный ключ не принимается. Потеря ответа /start оставляет неизвестный исход без повтора. Старые клиенты отклоняются до выдачи задания. |
| 3 | Подтверждено. SYSTEM требует Python в Program Files; проверяются владельцы, права записи и точки перенаправления всего дерева, включая библиотеки, и предсуществующих файлов клиента. Проверка консервативна и может потребовать исправления нестандартной установки Python администратором. |
| 4 | Подтверждено. Заданы AllowStartIfOnBatteries и DontStopIfGoingOnBatteries. Объект настроек проверен без регистрации новой задачи. |
| 5 | Подтверждено как зависимость от политики. Установщик и исполнитель проверяют разрешение неподписанных файлов и FullLanguage. При запрещающей политике — понятная ошибка, без Bypass или изменения GPO. AppLocker/WDAC автоматически не перенастраиваются. |
| 6 | Подтверждено. Ответ сохраняет начало/конец, превышение 128 КиБ больше не убивает команду. Отдельный порог аварийного дискового вывода — 100 МиБ суммарно. Проверено на выводе 200 КБ и exit 7. |
| 7 | Подтверждено. Ротируемый client.log, ошибки будущих результатов работников наблюдаются. Сервер пишет ошибки с типом и кадрами стека, неудачные авторизации — с адресом запроса. Секреты, скрипты и ответы не журналируются. |
| 8 | Подтверждено. Ошибки итерации не завершают цикл; добавлена проверка формы ответа и тесты IncompleteRead/отсутствия job. Ошибки конфигурации пишутся в client.log рядом с client.json; при невозможности открыть журнал используйте ручной запуск для диагностики stderr. |
| 9 | Подтверждено. Windows Job Object с KILL_ON_JOB_CLOSE, создание приостановленным и назначение до ResumeThread. Проверены потомок после выхода PowerShell и завершение задания после принудительного падения клиента. Процессы внешних служб вне Job Object не охватываются. |
| 10 | Подтверждено отсутствие функций. Добавлены TTL ожидания, cancel до начала, list, last_seen последнего poll и submit --wait. Работавшие команды не отменяются через API. |
| 11 | Частично исправлено. Добавлен явный proxy. PAC, NTLM/Kerberos и закрепление сертификата не реализованы. TLS-инспекция доверенным центром остаётся частью модели доверия. |
| 12 | Подтверждено отсутствие индексов/WAL/очистки. Добавлены индексы выдачи, срока выдачи, TTL и завершения, WAL и локальный purge завершённой истории. Long polling отложен; собственные замеры автора отзыва на 50/200 тыс. записей здесь не воспроизводились. |
| 13 | Подтверждено. Блокировка spool средствами ОС исключает второй экземпляр с тем же каталогом. Разные конфигурации с разными spool остаются ответственностью администратора. |

## Дополнительные изменения и границы

- Добавлен необязательный read_token: только status/list, без submit/cancel.
- Документация описывает ротацию токенов, недоверенный вывод ПК и подтверждение
  разрушительных действий оператором. Эти правила не заменяют подписи скриптов или
  отдельный механизм согласования на сервере; они пока не реализованы.
- Из текущих публичных файлов удалены реквизиты конкретного развёртывания; примеры
  используют remote.example.com. Личная заметка хранится локально в игнорируемом
  каталоге. Уже опубликованная история пока не переписана: для этого нужен отдельный
  согласованный force-push, а внешние копии и кэш GitHub могут сохранить старые данные.
- Подробный порядок совместного обновления клиента/сервера и миграции SQLite описан
  в [инструкции](HTTPS_TRANSPORT.md). Перед обновлением сделайте резервную копию базы
  и spool. Новая версия не совместима со старым протоколом выдачи.
- Защита рабочей машины не отключается. Настройка служебного доступа с рабочего ПК
  должна соответствовать правилам организации.

## Проверка

`python -m unittest discover -s tests -v`: регрессионные тесты очереди, leases,
spool, сети, токенов, TTL, отмены, параллельности, лимита вывода и Windows Job Objects.
PowerShell-синтаксис установщика проверен отдельно. Проверены флаги батареи.
Полная привилегированная установка SYSTEM и установка при различных доменных GPO
на этой машине не выполнялись; для них нужна отдельная тестовая Windows-среда.

Справочные материалы Microsoft: [политики PowerShell](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies/),
[Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).
