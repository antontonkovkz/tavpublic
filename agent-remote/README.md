# agent-remote — удалённое управление ПК с сервера

[English](README.en.md)

agent-remote позволяет оператору или AI-агенту на сервере выполнять команды на
удалённом Windows-ПК и получать результаты. Клиент работает в фоне и сам
подключается к серверу по HTTPS. Основной вариант не требует Chisel или SSH
на клиенте либо сервере, а также открытия входящих портов на ПК.

## Как это работает

1. Оператор на Linux-сервере отправляет PowerShell-скрипт в очередь.
2. Windows-клиент получает задание через исходящее HTTPS-соединение.
3. Команда выполняется отдельным процессом PowerShell без консольного окна.
4. Клиент возвращает стандартный вывод, ошибки и код завершения; сервер сохраняет результат.

Так можно работать с файлами, Git, сборками, процессами и службами в пределах
прав учётной записи клиента. Управление мышью, экраном и окнами приложений пока
не реализовано. Передача файлов и отмена уже работающих команд также пока не реализованы.

## Возможности

- Несколько команд одновременно: параметр `workers` от 1 до 32, по умолчанию 4.
  Остальные задания ждут в очереди. После изменения настройки нужен перезапуск клиента.
- Сохранение заданий и результатов в SQLite на сервере.
- Таймауты выполнения, ограничение вывода и отдельный результат для каждого задания.
- Срок ожидания задания, отмена до начала исполнения и список заданий/клиентов.
- Сохранение готовых ответов на клиенте и повторная отправка после обрыва связи.
- Отдельный токен каждого ПК и отдельный токен оператора.
- Запуск клиента при входе пользователя или при загрузке Windows от SYSTEM.

Клиент подтверждает начало отдельно: неподтверждённая выдача возвращается в очередь
через 60 секунд. Подтверждённые команды не перезапускаются автоматически: они могли уже изменить ПК.
Перед повтором задания с неизвестным исходом проверьте фактическое состояние машины.

## Установка и настройка

**[Подробная инструкция](HTTPS_TRANSPORT.md)** — установка API и systemd-службы
на Linux, HTTPS через Caddy, установка Windows-клиента, настройка параллельности,
остановка, возобновление и диагностика.

На сервере нужны Python 3.10+ и HTTPS-прокси с действующим сертификатом.
На Windows нужны Python 3.10+ и рекомендуется `truststore` для системной проверки
сертификатов. Для обычного управления не требуется запуск клиента от SYSTEM;
выбирайте права с учётом выполняемых задач.

| `windows_job.py` | Выполнение в Windows Job Object без осиротевших процессов |

## Пример выполнения команды

Создайте UTF-8 файл `command.ps1`:

```powershell
$ErrorActionPreference = 'Stop'
whoami
hostname
Get-Date -Format o
```

На сервере с подготовленной конфигурацией:

```bash
python3 https_remote.py submit --config /etc/agent-remote-https/operator.json windows-1 --script-file command.ps1 --timeout 300
python3 https_remote.py status --config /etc/agent-remote-https/operator.json JOB_ID
```

Первая команда возвращает ID задания. Подставьте его вместо JOB_ID во второй.
Для параллельной работы отправьте несколько заданий без ожидания предыдущего.

## Проверка проекта

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют очередь, разграничение токенов, сохранение заданий, параллельный
PowerShell и таймаут. PowerShell-тест выполняется только на Windows.

## Альтернатива: SSH через Chisel

Для Ubuntu-клиентов или существующей SSH-инфраструктуры сохранён отдельный
вариант с обратным SSH-туннелем через Chisel. В нём Chisel нужен на обеих сторонах,
а команды выполняются через `scripts/ai_client.sh`.

**[Установка альтернативного варианта SSH/Chisel](CHISEL.md)**.
Этот вариант независим от основного HTTPS-транспорта.
